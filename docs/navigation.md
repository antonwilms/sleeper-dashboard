# Navigation map

Per-file detail for `sleeper-dashboard`. Rules and invariants live in
[CLAUDE.md](../CLAUDE.md); this file answers "which file do I edit?" and "what shape is the data
that reaches it?" Rows are present-tense — they describe what a module does now. History lives in
`git log`.

### Routing / IA

HashRouter (`react-router-dom`). Grouped nav IA: **MANAGE** (Portfolio, Market, Teams) ·
**LEAGUE** (Standings, Schedule, Rosters). There is no ACT group — Trade desk and Draft board are
both gated placeholders, and a rail group with a dead third undermined the rest of it; their routes
stay live and reachable by URL, simply not linked from the rail or tab bar (no redirects — unlike
`/roster`/`/players` below, these are unbuilt routes, not retired ones):

| Path | Surface |
|---|---|
| `/` | → redirects to `DEFAULT_ROUTE` (`/market`) |
| `/portfolio` | Portfolio — header, four metric tiles, value-by-age-band chart, holdings table, row click → the detail pop-up |
| `/market` | Market — table over `playerRowsWithProj`: Value/Outlook/Volume/Efficiency column-set switch, position pills, sort, pagination, row click → the detail pop-up |
| `/teams` | Teams — the 32-team index: PROE/pace/success/off EPA-play/RZ TD%/def EPA allowed/pts-per-game + a YOUR EXPOSURE column, sortable, no pager. Rows are clickable (whole-row + keyboard, via `useNavigate()`), navigating to `/teams/:abbr`. Four FPA columns — `FPA QB`/`FPA RB`/`FPA WR`/`FPA TE`, blended per-game fantasy points allowed (`src/utils/opponentStrength.js`), rank 1 = toughest, no colour (polarity stated in text/popover only); ascending-first via `usePlayersTable`'s `ascByDefault`. The blend's current-season term is reachable (App.jsx's `currentSeasonTotals` loader, `src/api/sleeperStats.js`'s `loadCurrentSeasonTotals`) but not yet populated — `nfl/season-totals/<year>.json` for the live season won't exist until the data repo's weekly cron completes its first run after week 1 (see `opponentStrength.js`'s own header) — so this still renders the last-completed-season rate alone today; the popover states which season(s) are actually in play and, once the current season populates, the exact per-team blend weight |
| `/teams/:abbr` | Team detail — four 14-season metric cards (PROE/pace/success rate/off EPA per play), team holdings, and a coaching block. Reads `:abbr` itself via `useParams` (`App.jsx` is route-unaware; `LeagueView.jsx` is the precedent) |
| `/board` | Board (gated placeholder — marginal-value engine + season-phase classifier), nav label "Draft board" — route-only, not in nav |
| `/roster` | → redirects to `/portfolio` (retired route; old bookmarks/back-history don't 404) |
| `/players` | → redirects to `/market` (retired route; old bookmarks/back-history don't 404) |
| `/trade` | Trade (gated placeholder — marginal-/phase-aware trade evaluator), nav label "Trade desk" — route-only, not in nav |
| `/league` | → redirects to `/league/standings` |
| `/league/:view` | League group (standings / schedule / rosters) |
| `*` | → redirects to `DEFAULT_ROUTE` |

`/players` (the Explorer) no longer exists — the route redirects to `/market` above.
`COLUMNS`/`POSITION_STAT_COLUMNS` (the two column-descriptor maps Market's Outlook/Production sets
harvest) live natively in `src/components/market/columnDescriptors.js`; `DYNASTY_GROUP_MAP`/`NFL_TEAMS`
live natively in `src/utils/marketFilters.js`.

Nav chrome: desktop left rail (`NavRail`, grouped `NAV_GROUPS`) + mobile bottom tab bar
(`BottomTabBar`, flat `PRIMARY_NAV`, capped at 5). `NAV_GROUPS` references `PRIMARY_NAV` entries by
`key` (a small lookup), not array index — a positional reference (`PRIMARY_NAV[2]`/`[3]`) would
silently re-point groups at whatever shifted into those slots if `PRIMARY_NAV` changes shape.
Seasonal **Rookies** item Jan–May only (appended to the rail's MANAGE group and to the tab bar's flat
list; hidden offseason). League destinations are reached directly from the rail's LEAGUE group on
desktop; on mobile, via `TopBar`'s mobile-only League link (`/league` → `/league/standings`) plus
`LeagueView`'s own in-page sub-nav (`md:hidden`, the only mobile path to
`/league/schedule`/`/league/rosters`). `DEFAULT_ROUTE=/market` — Market is the app's data-display
centre of gravity; Portfolio is one click away in the rail. See `src/components/shell/navItems.js`.

### src/
| File | Responsibility |
|------|----------------|
| `main.jsx` | Entry point — renders `<App>` in StrictMode |
| `App.jsx` | Root component; owns all state; builds playerRows pipeline; renders the router + nav shell (`components/shell/AppShell`) and injects pipeline outputs into routed surfaces |

> **Color tokens:** `src/index.css` `@theme` is the color source of truth — neutral/surface role tokens + chromatic primitives (`--c-{hue}-{shade}`) + semantic aliases (accent/positive/negative/warning/caution/market/confidence/chart/phase), each with light + dark values (dp-v2 Slice 0: the app is dark-only, so a new token now takes a single value — the existing `.dark` block and its overrides stay, but the block is not extended). `--color-canvas` is the page ground (painted on `body`); `--color-surface…surface-5` are the cards/panels/fills that layer above it (light = warm, surface lifts above canvas; dark = cool near-black, lighter-as-higher). Components consume tokens (`bg-[var(--…)]`), never raw palette classes.
>
> **`--color-dp-*` / `--font-dp-*` (Dynasty Portfolio redesign, 1b Slice i):** a second, **dark-only** token family — no `.dark` override, by design (master-plan §4/§5.1). Scoped to new route **content** only: `Portfolio`/`Market` screen bodies (Slices iii/iv) and the player-detail pop-up (Slices ii/v). **Not** used by `TopBar`/`NavRail`/`BottomTabBar` — the shared chrome stays on the `--color-*` family above, unchanged, wrapping `League`/`Board`/`Trade`. Every `--color-dp-*` surface's outermost element must paint its own ground (`bg-dp-canvas`/`bg-dp-card`) before using any `text-dp-*` class. Fonts: `--font-dp-sans` (Public Sans Variable) and `--font-dp-mono` (IBM Plex Mono, imported as explicit 400/500/600 weight subpaths — the package root is 400-only). dp-v2 Slice 1 added `--color-dp-muted-3` (percentile-strip caption) and `--color-dp-pip-off` (unfilled coverage pip) — single value each, per Slice 0's amended rule above, not added to the `.dark` block.

| `portfolio/Portfolio.jsx` | Real Portfolio screen: header + `N skill players` subline, four metric tiles, a value-by-age-band chart, and a holdings table (ASSET/VALUE/5-YR PPG/PROJ Δ/HORIZON), row click/keyboard → `onOpenPlayerDetail`. Scoped entirely to `ownerTeamName === myTeamName` rows, derived once and shared by every section. No column-set switch, no position pills, no pager (table shell is inlined here, not `MarketTable`) — see `dp/cells.jsx`. `HORIZON` reads `row.dynastyScore.signals.yearsFromPeak` (pipeline-computed, not re-derived); the age-band chart intentionally uses fixed position-blind bands instead (aggregating *value* across a roster, where position-blind bands are the point) — the two deliberately disagree occasionally. Reconstructs pick ownership (`utils/tradedPicks.js`'s `deriveLiveSeasons`/`reconstructPickOwnership` — live seasons are the *intersection* of "KTC prices this season" and "≥ first-live", so a season whose draft already happened is excluded rather than double-counted against players already rostered) and prices each live pick at KTC's `Mid` tier (`utils/ktcPicks.js`'s `parseKtcPickRows`/`pickPrice`; round 5+ and any season KTC doesn't price render a dashed `—`, `PROVISIONAL(no-data)`, never `0`, counted inline as `+ N UNPRICED ASSETS`). Picks render in the SAME holdings table as players (a `PickCell` ASSET-column analogue of `PlayerCell`, meta line `own pick` / `via <original owner>`), sorted by the same `ktcValue` key (unpriced sinks via `compareNullsLast`) — but picks are plain `<tr>`s, not `ClickableRow` (which hard-codes `onOpen(row.player_id)`; a pick has no `player_id`). A priced pick's VALUE cell is a `DefinitionPopover` trigger showing all three KTC tiers (`Early N · Mid N · Late N — priced at Mid`) in `gloss`, deliberately **not** `percentiles` (that prop means a league percentile distribution; three tiers of one asset is a different shape). Two tiles carry real deltas (ROSTER VALUE, CONCENTRATION — both labelled `players only`, since `loadKtcHistory` drops picks the same way `matchKTCToSleeper` does; near-static pick prices, median 1.3% move over the 8-snapshot window, justify the omission rather than assuming it away) computed as a constant-portfolio measure (today's holding set held fixed, only price varies across the window — reports market movement, not the effect of trades); the other two (WEIGHTED AGE, PROJ. POINTS) render `DegradedBlock` `no-baseline` unconditionally — no historical aggregate of either is ever stored, a storage fact stated plainly. The "· N rookie picks" subline clause stays cut |

EFFICIENCY is per-position (QB / RB / WR-TE, ~5 columns each), a single season pinned to `dataSeason` (the season `<select>` stays hidden, unlike Volume's user-selectable one; the header states the fixed season and the gp≥8 limitation rather than hiding it). Columns: QB `EPA/ATT`/`CPOE`/`SACK%`/`AY/ATT`/`RUSH EPA`; RB `CARRY SH`/`TGT SH`/`RUSH EPA/ATT`/`YAC`/`BTKL`; WR/TE `TGT SH`/`AY SH`/`aDOT`/`EPA/TGT`/`RACR`/`RZ SH`/`SNAP%`/`DROPS` (`ALL` reuses WR/TE's list). Three derivations back it: `src/utils/seasonEfficiency.js` (one-pass gamelogs aggregator, memoised on the loader result + `dataSeason`, REG-only, sum-then-divide; `CPOE` is attempt-weighted, `Σ(passingCpoe × attempts) ÷ Σattempts`, since it's a per-game rate and a plain mean would let one low-attempt game dominate; `CARRY SH` is its one cross-family join, `Σ carries ÷ Σ teamcontext.off.rushPlays` matched `(team, week)` — deliberately wider than the per-season-team rush share elsewhere, since `off.rushPlays` includes QB scrambles/sneaks; its `resolvePlayerTeam` calls are pre-filtered to REG games, since that helper's week-grain lookup is seasonType-blind); `RACR` from the `advStats` prop (`byId[id].racr`, gated on `complete`) rather than re-derived from gamelogs; and `TGT SH`/`AY SH`/`aDOT`/`RZ SH`/`SNAP%` reuse `buildPositionStatSeries`/`buildRzShareSeries`/`buildUsageHistory` but take the latest entry only when its season equals `dataSeason` — those helpers gate at `gamesPlayed≥8` (shared with the projection's attribution, never forked), so all five render `—` for roughly the first half of every season, stated in the header rather than worked around. `METRIC_META` (`usageEfficiency.js`) is the single metadata source for all of it. Column-set switches and position-pill clicks while Efficiency is active re-assert that POSITION's own lead metric (`EFFICIENCY_LEAD_SORT`: QB→`EPA/ATT`, RB→`CARRY SH`, WR/TE→`AY SH`) via the `setSortState` escape hatch — `DEFAULT_SORT` alone can't express a per-position default, only a per-set one. Four props (`gameLogsByYear`/`teamContextByYear`/`historicalTeamTotals`/`advStats`) feed Efficiency — Market stays props-only (growing the explicit list is the accepted cost, not a signal to switch to `ProfileDataContext`). Four environment filters (Team PROE/pace/off. EPA-play/RZ TD rate) live in the filter panel — `rankTable`, a `useMemo(() => buildLeagueRankTable(teamContextByYear[dataSeason], FILTER_METRICS))` gated on that season's `complete` flag (not key presence — an incomplete load yields empty per-metric maps that would otherwise empty the table the moment a control moved), keyed to `dataSeason`, not the user-selectable `activeVolumeSeason` (the wrong one would silently re-join the filters to whatever season Volume's selector holds). Passed into `applyMarketFilters`'s widened ctx alongside `careerStats`/`season` for the `resolvePlayerTeam` join. See `marketFilters.js`'s row for the predicate/preset details. Dark-only `--color-dp-*` throughout; does not consume `ProfileDataContext` (gets its data as props from `App.jsx` — `careerStats`/`playerMap`/`seasonProjections`/`ktcHistory`, the last feeding the TREND gutter's series only). | `teams/Teams.jsx` | The 32-team index (`/teams`). Zero new fetching — reads `teamContextByYear[dataSeason]` plus `playerRows`; `dataSeason` via `environment.js`'s `deriveDataSeason(careerStats)` helper, not a local copy of Market's inline derivation. Columns: `TEAM · PROE ↓ · PACE · SUCC% · OFF EPA/PL · RZ TD% · DEF EPA ALL · PTS/G · YOUR EXPOSURE`, default sort PROE descending, one `computeTeamSeasonMetrics` pass per team via `buildTeamMetricsTable` — the 32 rows are driven by that loaded season's own `teams` keys (era-accurate domain), not `marketFilters.NFL_TEAMS` (Sleeper domain, carries `LAR`). `DEF EPA ALL` is the one inverted column — first click sorts ascending (best defences first, in `usePlayersTable`'s `ascByDefault` set) and colours negative blue / positive amber, the reverse of `OFF EPA/PL`; `LOWER_IS_BETTER` in `environment.js` is deliberately untouched (its only consumers, `computeLeagueStanding`/`buildLeagueRankTable`, are not called here — the surface owns its own direction and colour). `YOUR EXPOSURE` (why the surface exists) scopes to `ownerTeamName === myTeamName` and buckets each row on `normalizeTeamForSchedule(nfl_team)`, never raw `nfl_team` (`playerMap[id].team`, the Sleeper domain — CR-16's boundary; ungated, every `LAR` player would land in an unmatched bucket and `LA` would silently read `none`); the literal string `'FA'` (a real free-agent asset) counts in the value denominator only, so shares sum to ≤100% and are never rescaled to 100%. A team with nobody owned renders `none`/`—`, muted, not `0 players`/`0%`; a null `ktcValue` is skipped in both the numerator and denominator, not zeroed; `myTeamName` null renders the whole column `—`. A distribution strip (`dp/SeriesBars.jsx`) redraws under the header for the currently sorted column — passes `colour="neutral"` (a signed metric's raw sign is not colour-coded here, since `DEF EPA ALL`'s own inverted cell colours would otherwise contradict it). ## Patterns

### Caching (cache.js + IndexedDB)
- `getCache(key)` returns data or `null` (null on miss or TTL expiry)
- `setCache(key, value, ttlMinutes)` — default TTL 60 min; keys containing "players" default to 1440 min
- Pass TTL explicitly to make intent clear (see `sleeper.js`). Per-function TTLs, stale-cache invalidation, and the nflverse-via-data-store path: [docs/integrations.md](docs/integrations.md).

### Component data access (two patterns)
1. **Props from App.jsx**: `StandingsTable`, `ScheduleGrid`, `RostersTab`, `MyTeamView`, `Market`, `Portfolio` — all props-only, no context reads
2. **ProfileDataContext**: any `usePlayerProfile` consumer reads the fourteen-key value (see the `src/context/` table above) via `useContext`. **One provider site**: an App-level provider wraps `<Routes>` in `App.jsx` itself, feeding `dp/PlayerDetailTabs.jsx` (and, through it, `dp/PlayerDetailModal.jsx`) so the pop-up is mountable from any route
